# ADR01 — Use `output.json` directly as the non-regression test reference

## Status

Accepted

## Context

Before refactoring `updateBenefitValue`, we need a safety net proving that the
observable behavior of the 4 existing drugs (Doliprane, Herbal Tea, Fervex,
Magic Pill) does not change.

Two options were considered:

1. Copy `output.json` into a dedicated fixture (e.g. `__fixtures__/output.baseline.json`)
   and compare the simulation result against that frozen copy.
2. Import `output.json` directly in the test and use it as the reference.

## Decision

Use `output.json` directly as the reference, without duplicating it into a
separate fixture.

Reasons:

- `output.json` is already the frozen contract for the 4 existing drugs (README
  constraint: it must be generated identically). Duplicating it into a fixture
  creates two sources of truth that can silently diverge if one is updated
  without the other.
- `output.json` is regenerated by `yarn start`/`yarn test` (`index.js` script)
  with exactly the same logic (same initial drugs, same 30 iterations) as the
  one replayed in the non-regression test: a single data source to maintain.
- Fewer files to manage, simpler PR diff to review.

## Consequences

- If `output.json` is ever changed by mistake (regeneration bug, refactor that
  changes behavior), the test fails immediately — this is the intended effect.
- The test depends on a generated, versioned file rather than an explicitly
  hand-written fixture; this is acceptable here since `output.json` already
  has official reference status imposed by the test's specification.
